## Candidate evidence and limits

The research reports an isolated locked install and invented `renderAsync` probes on Node 20.6.0, 22.23.4 and 24.22.2: text and selected styles, a table and a PNG data URL with a valid signature. Its valid external `r:link` probe retained a hyperlink and produced `src="null"`; no request was observed on its instrumented paths, with one positive control. These are reported observations, not independent reproduction here: the stated ignored `.build/t4-node-research` artifacts were not present in this worktree or Controller tree. They do not prove image decoding, full browser layout, CSS sanitization, all network paths or installed-product behavior. R4 explicitly handles those shortcomings; no pre-build browser test is needed to choose the package.

The research includes a full entry-by-entry comparison of its two proposed whole-repo lock graphs, including relocations and importer changes; these are generated, uninstalled candidates, not the final release lock. The candidate 26 entry's version and integrity match the registry and its changed CSS/URL/parser closure confirms that changing the direct pin changes more than one artifact. The underlying candidate lock and output files were unavailable for independent integrity, graph completeness or probe reproduction; do not treat the reported audit or lock inventory as independently verified. Generate and review the actual lock against the final merge base with all approved #4 changes; install only with `npm ci` and normal lifecycle scripts. Preserve the 23 existing Linux optional `libc` metadata entries where feasible; otherwise explicitly review the diff and prove native selection on supported glibc and musl targets.

The [PDF registry metadata](https://registry.npmjs.org/pdfjs-dist/5.4.394) and current lock declare `>=20.16.0 || >=22.3.0`; the root engine also admits versions excluded by existing jsdom 29, including Node 21 and 23. A jsdom downgrade does not fix PDF or prove any other transitive runtime. Keep the advertised policy unchanged and test the actual installed preview and dependency closure on the advertised supported Node versions and vendored Node before release or claiming compatibility; record exact failures and escalate any real incompatibility. Engine metadata alone does not prove execution, and the reported 24.22.2 probe is not the 24.22.1 vendored archive.

## Binding package and release checks

- Verify actual artifact integrity, all resolved nested and native packages, licenses and applicable notices in both the source tarball and post-prune payload. The research's standalone inventory lists `isarray` and `saxes` without a root named notice; inspect their source and obligations, not just root filenames. Review JSZip's MIT choice and pako notices; carry all other package and vendor notices from the prior package review. Record the actual file count against the existing 2,500 ceiling; do not silently raise it.
- Audit the actual release closure, including non-registry SheetJS and all nested copies. The candidate audit reports [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq) on nested uuid 8.3.2 through ExcelJS. The prior review inspected a v4 call without a supplied buffer in the specified read path; confirm the installed graph and usage, record the advisory and reassess changes. It does not establish safety of other paths or absence of other vulnerabilities. Review actual tmp and unzipper resolutions; do not silently add an override or equate an empty audit with safety.
- K1 proves actual source-tarball and pruned archive installations outside the checkout, exact package and child resolution, absent/wrong-version failures, dynamic assets, native binaries and notices, with no source/global fallback. Keep PDF assets and the approved Koffi/Windows non-opening probe obligations. P3/B4, actual route-to-child-to-browser, image dimensions and sanitization tests are future proving work, not completed checks or extra package-decision prerequisites.
