## Findings

### F1 — Design-relevant: freeze the contracts, including HTML revalidation

The route summary identifies names but leaves PDF/Word/XLSX result fields, nesting, units, empty sheets, notices, error codes and actual child job/result protocol as “validated child result”. UI producer and consumer cannot independently implement that interface. Pin the exact definitions and validators to specific files and lines at `f919c8a`, including `WorkspacePreviewJob`, worker result validation and the corresponding preview consumers, or include equivalent complete field tables. Specify types, optional fields, every success and error status/code, MIME and security headers, path normalization, concurrency/admission, timeouts, cancellation and identity checks. Name the test that sends real child output through the actual route to each real consumer. Internal TypeScript exports may use the pinned fork signatures; do not expose new package APIs.

There is a concrete conflict: the draft requires current policy and target revalidation after reads, but the HTML branch in `apps/web-server/src/room-settings-routes.ts` at fork lines 360–393 reuses `effective.policy` for its post-read resolver rather than resolving the current policy. Copying it as-is does not establish the stated revocation guarantee. Specify fresh effective policy/read-tool revalidation and guarded target comparison before returning HTML, and a public-route regression that revokes access while the read is in flight. Keep the accepted sandbox, no-network policy and explicitly accepted self-navigation risk. Do not present the fork's handling as proof of this guarantee.

### F2 — Design-relevant: independent branches lack a composition contract

Both `agents/upstream-series-1` and `agents/upstream-series-2` currently start at `461e6485`; the draft identifies overlapping shell, route and image-helper changes but does not define what series 2 builds against or how independently developed changes combine. A later merge can replace read-only Markdown with an editor, conflict in `App.tsx`/routes and lockfile, or leave image handling and tab state inconsistent. Series 2 scope (editor, drafts, keep-mine, workspace images and search) is binding; no editor dependency may be required to build or run series 1 alone.

Before parallel implementation, the Controller must specify the exact shared file/module ownership and signatures, tab identity/state and Markdown transition, image route/helper contract, dependency and lockfile reconciliation, merge/order strategy and whether each branch's acceptance is measured against base or a composed tip. Each independent branch must build on base without the other; the combined result must retain both series' acceptance and the original policies. Assign one owner and prerequisites for a test using the real series-1 route producer and series-2 consumer in the composed tree, covering open Markdown, local and blocked external images, draft conflict/keep-mine and navigation. Do not merely mock the other series or silently stack one branch on the other. If composition changes an accepted boundary, return for review.

### F3 — Design-relevant: acceptance scope and failure behavior need an unambiguous table

The draft proposes `.md` through text preview with 16,777,216-byte replacement UTF-8, whereas fork Markdown uses 128 KiB strict UTF-8/NUL checks; it explicitly leaves the choice open. The dispatch decides read-only, not encoding or cap. Recommend the proposed bounded inert text behavior, no Markdown GET/PUT/editor, revisions, save or Open action; Controller must explicitly adopt it. Test empty, malformed UTF-8, NUL, at/over cap, no write route, guarded access and real browser display. This is a level-2 contract within ADR-0002, not a new editor decision.

ADR-0004 explicitly includes `.drawio`/`.dio` as open-only; retain their no-preview state and local Open, with public route and browser tests. `.xlsm` is open-only and `.xls` unsupported, also under ADR-0004. The held #12 concerns the right pane, not authorization to import held changes or add XLS support; preserve existing base behavior outside the approved preview integration and give #12 no implementation in this series. #16 is a separate single commit at the end of series 1. No Excalidraw code, route, frame, dependency or notice enters this slice.

Complete one extension-by-extension table of tree selection, preview type, error-only state, open eligibility, MIME, and local/paired behavior. State loading, empty, unsupported, revoked, unavailable and failure outcomes, selected-tab identity and right-neighbour-then-left close; specify that existing tabs retain snapshots and closing/reopening reloads under current policy. Explicitly require drag-to-composer. Trace every signed retained design acceptance to a public or browser test, including actual PPTX one-delivery/timeout, Word sanitization, spreadsheet stored values and formatting, and local and paired open controls. A skipped Chromium run is not acceptance.

### F4 — Design-relevant: dependency and packaging closure is not yet an approval

The candidate direct owners are server `docx-preview@0.4.1`, `exceljs@4.4.0`, `jsdom@26.1.0`, optional `koffi@2.16.2`, and UI `@aiden0z/pptx-renderer@1.4.0`; confirm exact root/bundle declarations and retained base `pdfjs-dist`, `@napi-rs/canvas`, `jszip` and SheetJS. The base server manifest lacks the new direct dependencies, and the fork's jsdom downgrade can affect existing `fetch_url`/other consumers. Do not approve a purported exact transitive lock from a fork inventory: peer/optional/native closure, `buffers` license, installed/pruned artifacts, supported engines/platforms, bundled files and required notices remain unverified. Fix the intended direct manifests, lock-generation method and a finite review/acceptance gate over the actual resolved graph, including jsdom existing-consumer regression and packaging/pruning checks. Record package/license sources and actual shipped bytes; exclude editor/Excalidraw artifacts and preserve base notices. No real API or opener in tests. Real Windows/Electron behavior is independently unverified and must remain visible as such.
