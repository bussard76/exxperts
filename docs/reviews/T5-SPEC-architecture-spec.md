## Prefactoring

No broad prefactoring is needed. Reuse or minimally extract the existing guarded workspace resolution for the tree and the write-purpose protections for PUT. Preserve the actual public HTTP seams and avoid a parallel weaker policy implementation.

## Findings

1. **Read authorization is not a fixed shared contract.** The spec says to enforce “appropriate tool permission” for Markdown and images but names only `ls` for tree and the write tools for PUT. On the feature branch, `requirePolicy` uses `workspaceToolsEnabled`; `resolvePersistentRoomEffectiveWorkspacePolicy` can enable that with any selected workspace tool or Bash, while the narrower `WithPolicy` helpers require a nonempty workspace-tool selection. Thus, for example, a Bash-only or `ls`-only selection can yield different answers depending on which interpretation is chosen. ADR-0002 requires existing tool-permission boundaries, and this is a material access-control choice. The Controller should determine the intended exact per-route read tool selection, including Bash-only, `ls`-only, write-only, no selected tools, and disabled read mode, against the existing policy and Sascha's decision; record it and matching local/paired route tests in the spec. Do not treat the branch's permissive behavior as approval. If the desired rule changes the accepted boundary, obtain the applicable decision before implementation.
2. **Outside-in sign-off is not established.** `docs/coordinator.md` requires signed-off UI, interface and logic evidence, including a `design/<feature>/` export and an agreed Mermaid logic diagram, before building new features. Only `design/README.md` exists, and issue #5 records an image trial, not sign-off of the full tree/editor, states and logic. The revised spec provides useful behavior and interface details but does not demonstrate that those required stages were signed off. The Controller should obtain and record the missing evidence, or establish an authorized resolution of the gate, before implementation; do not infer approval from the trial or invent a product decision. In particular, the logic must cover the editor's dirty, conflict, failed-save and navigation transitions and image-blocking behavior.

## Binding implementation and verification details

- Treat the spec's ten dependencies and four method/route pairs as proposals pending Controller review, not additional approvals from ADR-0002. The server and UI split, if used, must consume the same resolved authorization and error contract; the integrated browser test depends on both.
- Check requested and resolved paths with the relevant read **and write** policy, including the file and each ancestor; the branch currently calls `resolvePersistentRoomWorkspaceExistingFile` with purpose `read` during replacement. Keep a denied or changed grant from disclosing an alternate directory or filesystem path to a remote client.
- Verify source preservation for standalone, image-only linked, and mixed text/image linked Markdown, including literal and encoded spaces, using byte comparisons as specified. The branch's image-only link parser does not preserve the mixed case. Untested HTML `<img>` attributes remain a debt candidate unless needed for the stated requirement.
- The accepted ADR resolves the prior review's two Sascha decisions; no new proposed ADR is appropriate on the evidence here. No tests or suites were run for this read-only review. The browser flow must actually run, not skip for a missing Chromium executable.
