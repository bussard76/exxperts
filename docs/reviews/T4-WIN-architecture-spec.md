## Architecture impact

The approved data flow remains explicit preview-header click → authenticated, affirmatively local room POST → current workspace guards → private server opener → OS-assigned application. Koffi is already a project dependency; native calls and the disposable child implement the replaceable internal opener contemplated by ADR-0003. They introduce no additional browser/desktop authority, generic command facility, public package export, store, agent tool or external service. Keeping native blocking/crashes outside Fastify is necessary for the specified responsive 10-second deadline. This does not require a new architecture choice beyond the recorded Controller selection within ADR-0003.

The server's new optional dependency ownership, exact pin, native payload retention and child asset must be explicitly included in Controller's implementation dispatch as described below; the ADR alone does not approve them. A different FFI package, desktop bridge, native helper download, shell fallback or application override would require renewed review. `ARCHITECTURE.md` is absent and `factory.config.json` has architecture mode off; the applicable baseline is AGENTS.md and accepted ADR-0002/0003.

## Findings

No design-relevant blocker remains in the selected Windows direction. R2 still says “B-WIN unresolved” and “not selected/approved” at lines 299, 333 and 386; Controller's later selection supersedes those statements for Windows. Carry the selection and B1–B4 into the final build spec rather than asking the Developer to choose among the research options. These are precision instructions for the selected design, not evidence of an implemented or tested adapter.

### B1 — Fix the native declaration, lifetime and error contract

- Where: research:64–90, 102–112, 142–146; R2:299–303.
- Required: use synchronous calls on the child's same main thread, with Win32 calling convention declarations. ShellExecuteExW returns signed int32 BOOL and takes an input/output pointer; CoInitializeEx returns signed int32 HRESULT, CoUninitialize returns void, GetLastError returns uint32, and SetLastError takes uint32. Use UTF-16 pointers, uint32 DWORD/ULONG, int32 nShow and pointer-sized handles; no C `bool`, Unix-sized `long`, packed layout or two consecutive union fields. Microsoft's [Windows types](https://learn.microsoft.com/en-us/windows/win32/winprog/windows-data-types) and [ShellExecuteExW declaration](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw) support those declarations. Koffi's [input/output guidance](https://koffi.dev/output) explains why cbSize needs `_Inout_`.
- The research's x64 offsets are correct by derivation from the SDK declaration and Microsoft's [x64 layout rules](https://learn.microsoft.com/en-us/cpp/build/x64-software-conventions?view=msvc-170): offsets in field order are `0,4,8,16,24,32,40,48,56,64,72,80,88,96,104`, alignment 8, size 112. Require `sizeof`/`offsetof` assertions against these literal expectations before dispatch. This is a documentary derivation, not a measurement with a Windows compiler or Koffi. The reviewed release target is win-x64; do not apply its layout to another architecture or claim another target is verified.
- Initialize COM with null reserved pointer and flags `0x6`; accept S_OK (0) and S_FALSE (1), balancing either with one CoUninitialize on the same thread. Initialization failure, including changed apartment mode, means unavailable and zero ShellExecute calls. No asynchronous Koffi call or worker-thread hop. This follows [CoInitializeEx](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-coinitializeex) and [COINIT](https://learn.microsoft.com/en-us/windows/win32/api/objbase/ne-objbase-coinit).
- Adopt the proposed fixed fields: cbSize 112, mask `0x500`, verb `open`, unchanged unquoted guarded file, nShow 1, all unused fields null/zero. NOASYNC completes the short-lived caller's handoff; NO_UI suppresses ordinary error dialogs, **not security prompts or the application's UI**. Request no process handle and wait for no application exit. Microsoft's [SHELLEXECUTEINFOW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow) supports these fields and lifetime requirements. Do not add environment substitution, association chooser, elevation or zone-check bypass flags.
- Bind trusted system functions before opening. Bootstrap through fixed kernel32, obtain the system directory with GetSystemDirectoryW, then load absolute shell32/ole32 paths. Check zero and insufficient buffer results rather than assuming `C:\Windows` or an environment override. The [system-directory contract](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemdirectoryw) and [DLL search rules](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-search-order) support the approach; the latter does not prove a particular host's KnownDLL list. The safe Windows probe must verify the bootstrap's resolved system modules. Set child cwd to its trusted packaged asset directory, never the workspace.
- SetLastError(0) immediately before ShellExecuteExW; when BOOL is zero, GetLastError must be the next native call, before COM cleanup/logging. Never use `koffi.errno()` or legacy hInstApp numbers as Win32 errors. [GetLastError](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-getlasterror) is thread-local and must be captured immediately; [SetLastError](https://learn.microsoft.com/en-us/windows/win32/api/errhandlingapi/nf-errhandlingapi-setlasterror) defines the reset. Research E6 supplies the pinned Koffi preservation evidence; this review did not execute or independently re-read that addon source.
- Fix application mapping: BOOL nonzero alone supplies native acceptance, including null hProcess; false with 1155/126/1157 → 503 `opener_unavailable`; false with 1460 → 504 `open_timeout`; false with 2/3/5/32/193/1156/1223, zero or any other code → 500 `open_failed`. Include the documented noninteractive-window-station error 1459 as 503 unavailable. Constants are confirmed by Microsoft's [0–499](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-), [1000–1299](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1000-1299-) and [1300–1699](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1300-1699-) lists; this HTTP classification is the application contract, not a promise that Windows returns only those errors. A visible application is never inferred, including on a headless host.
- Proof: O3 through the public POST and production adapter, faking only native/process operations, checks declarations, literal fields, valid Unicode/surrogate paths, COM cleanup, error ordering and every response class. Windows-illegal filename characters such as double quotes belong in refusal cases with zero dispatch, not a claim that such a file was opened. No real ShellExecute call is permitted in worker tests.

### B2 — Fix the private producer–consumer contract and settlement

- Where: research:67, 94–96; R2:287 and O3/K1.
- Required private request: exactly `{ path: string }`, sent once over IPC by the parent after current guards; no other property. The child accepts one nonempty, NUL-free absolute Windows file path, with no URL/device/UNC/ADS expansion, and never another request. Its validation supplements the parent's authoritative workspace guard; the child receives no room policy or credential. No path arrives in argv or shell text.
- Required private result: exactly `{ accepted: true }` or `{ accepted: false, code: "opener_unavailable" | "open_failed" | "open_timeout" }`; no extra fields, maximum 256 serialized bytes. The child maps native failures using B1, completes matching COM cleanup, then sends one result and waits for IPC send completion before disconnecting/exiting. No raw host diagnostic is sent to the browser. Missing library/export, wrong addon/version/layout or COM failure yields unavailable; an unexpected exception yields failed.
- Parent starts its 10,000 ms deadline before child launch, validates the result, and settles once. Spawn success, exit code zero, disconnect, malformed/empty/oversized IPC, crash and late messages never supply acceptance. Child launch ENOENT/ENOSYS maps unavailable; EACCES/EPERM and other process/protocol failures map failed. If `exit` races an in-flight result, drain IPC/observe `close` within the same deadline before concluding no result; do not copy the shelf worker's timing grace as the protocol.
- Use fixed current plain-Node `process.execPath`, fixed sibling `.mjs` asset, explicit execArgv with no inherited loaders, `shell:false`, `windowsHide:true`, no detached mode, and an environment without NODE_OPTIONS/NODE_PATH overrides. Dispose only the dispatcher on timeout/client abort, with no retry or process-tree/application kill. Return timeout without waiting indefinitely for cleanup; observe cleanup for at most another 1,000 ms and record a bounded, path-free cleanup fault if still unreaped. Native acceptance can have happened before a lost reply/timeout; do not claim rollback or cancellation.
- Proof: one invented-file request through the actual route → production parent → actual child protocol → fake native seam → parent → HTTP response, including packaged execution in K1. Also prove false/unknown/COM failure, exit-before-result delivery, malformed IPC, timeout/late reply, client abort and single settlement with controlled fakes. A fake opener that bypasses the parent/child cannot replace this integrated proof. No runtime request, environment switch or public export may select a test opener.

### B3 — Make the selected package and installed asset ownership explicit

- Where: research:120–130; `package.json:136`, `apps/web-server/package.json`, `scripts/bundle-server.mjs:50,139,380,420`, `scripts/bundle-server.test.mjs:311`, desktop prune code.
- Required build-dispatch declaration: root optional Koffi **2.16.2**, direct server optional Koffi **2.16.2**, existing production-lock integrity retained. Pin these consumer declarations exactly rather than relying on root `^2.9.0` for an installed tarball; do not upgrade Koffi. The unrelated TUI optional range may stay as is; verify that the opener's actual resolution is 2.16.2 and reject another version as unavailable. No new third-party identity or runtime/TUI API change is needed. Controller must explicitly include this ownership/pin policy in its package approval.
- Set the existing Koffi external to `ships:true`, with its server child reason; do not duplicate it in FILE_PACKAGES. Register the fixed private `.mjs` in BUNDLE_ASSETS and its owning location read. Extend the existing private-worker import check, currently hard-coded to the shelf worker at line 420, to inspect this actual child too. Keep lazy Windows-only native loading so non-Windows startup does not import the addon.
- Retain the full installed Koffi package initially, matching win32_x64 addon and package loader/version, and its LICENSE/vendor/cnoke notices. Existing package closure and desktop keep rules can do this; no new native copier or broad desktop keep entry is justified. `ships:true` makes package presence required on every trimmed target with today's platform-independent closure; optional runtime failure handling does not waive release completeness. Do not silently add target-conditional pruning or raise the file ceiling.
- The existing forbidden-Koffi-import test becomes stale when Koffi ships. It must retain its unshipped-external rejection assertion using a genuinely unshipped example, with explicit Controller approval under AGENTS.md's test-correction rule, plus new Koffi retention coverage. Never delete/skip/loosen it merely to obtain green results.
- Proof: K1 covers source tarball and post-prune desktop/archive installs outside any checkout, actual child resolution, pinned version, addon and notices, missing-child/package/addon/version cases, and measured file count. Manifest presence alone is insufficient: `checkServerFiles` currently checks assets/manifests, not successful native loading. Missing optional installation yields honest runtime unavailable; a supported Windows release still must pass its native-load gate.

### B4 — Separate safe native proof from real opening acceptance

- Where: research:138–149; R2:359–363; Controller Windows direction.
- Required: on an explicitly approved Windows test host, a non-opening probe under both ordinary installed Node and the packaged vendored node.exe loads exactly Koffi 2.16.2 from the installed payload, binds system exports, checks literal layout/constants and COM init/uninit. Check last-error preservation safely using SetLastError/GetLastError, not ShellExecuteExW. Record target architecture, Node/Koffi version, resolved module paths and probe outcome without user data. Binding ShellExecuteExW is allowed; invoking it is not. No fixture association installation or registry modification is required.
- Fake O3/K1 tests prove orchestration and mapped native outcomes; the safe probe proves loading/layout/thread prerequisites. Neither proves DDE/COM association handoff, no-association behavior on an actual host, or application display. Those observations remain Sascha's later acceptance on his own computer. A missing safe probe blocks a claim of verified Windows packaging, not authoring this already specified adapter after #5 and package authorization. Do not reopen option A, omit Windows, add a helper, or authorize a real opener to manufacture evidence.

## Debt and limits

No observed functional defect requires a changed design. Target-only Koffi payload minimization, broader association-handler coverage and deeper native supply-chain review are bounded later debt candidates, not grounds to change this spec. The pathname replacement race is already recorded; the adapter cannot eliminate it or guarantee that an external application is read-only. No claim is made that NO_UI suppresses security prompts or external application effects.

No product code, tests, fixtures, dependencies, Controller files or real data were modified; no tests, builds, browser, Docker, native addon, real opener or model API were run.
