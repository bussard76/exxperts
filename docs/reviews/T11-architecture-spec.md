## Prefactoring

None required in advance. Keep the existing worker and packaging seams; choose the smallest implementation supported by evidence. If bundling is needed, account for worker dynamic imports, native/file-loaded dependencies, bundled license notices and existing build guards, rather than assuming the server bundle's rules automatically apply to the worker.

## Findings

1. **Architecture impact and implementation missing.** The issue offers alternatives and an order to try them but does not record `## Architecture impact`, the package or stand-in contract, its ownership or how it reaches the actual consumers. A new dependency is level 2 and needs the Controller's decision after architect review. Record exact proposed modules, dependencies and interfaces, then obtain another spec review. If investigation reveals a new module, changed data flow, protocol or technology, stop and escalate as level 3 under the repository rules.
2. **Installed artifacts and desktop closure are unspecified.** Release `npm ci` honors the root override but a global tarball installation does not. Desktop retention is derived from package manifests, not merely the paths invoked by `.xlsx.load`; the issue's generic override or prune rule does not establish either route. Define how each supported install gets the intended files and how the real archive and desktop consumer are checked. Do not remove shared dependencies just because the spreadsheet stream reader does not call them.
3. **Acceptance evidence must cross the actual seam.** The existing route and browser smoke tests run against the source environment; `many.xlsx` in the browser test is an intercepted response, not a many-sheet workbook processed by the worker. Define packed-output tests that demonstrate real workbook parsing and rendering, the other worker operations, preserved assets, controlled errors and both file limits. Use only invented files; retain the security and resource limits already accepted in ADR-0004.
