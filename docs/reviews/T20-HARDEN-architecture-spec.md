## Architecture impact

Level 3 remains correct even if hardening keeps the current filenames and uses no dependency. `apps/web-ui` must own one document session across two host documents, serialize transfer/close/navigation, and preserve one editor/save pipeline. `apps/desktop` must mediate normal native close before hide/quit and validate child placement against Electron displays. Those are new interfaces and responsibilities; ADR-0008's file-count clarification does not lower the level.

The server's existing room/workspace policy, Markdown revision checks, preview routes and explicit local OS-open authorization remain authoritative. Proposed scope adds no dependency, server route, public package export, draft recovery store, writer lease or independently running child. Geometry persistence must be explicitly specified and reviewed; the prototype's existing localStorage key is an observation, not accepted storage architecture. Any additional store, route, privilege or transport requires renewed architecture review.

## Prefactoring

The smallest candidate is ADR option A: retain one chat React owner and one live editor, isolate workspace-document rendering from the mixed right-pane occupants, and adapt events to the real host. Avoid a second `App`, room socket or synchronization store. The stable portal host is useful evidence, but does not establish that editor state survives native destruction or that frame messages reach the owner.

D `logic.md:43` proposes lifting recoverable session state; F keeps draft/baseline/revision/save state within `MarkdownEditorPane` and its surface. The spec must reconcile these: either prove the same live editor/session remains authoritative through every selected transfer path, or define the minimal owner-retained volatile snapshot before a host can disappear. Do not build both retention models speculatively. A single guarded-action arbiter is necessary because F's `markdownEditorPendingActionRef` is overwritten by each dirty action. No broader App rewrite is justified.

### 2. Change-spec: normal native exit and correlated closure are not buildable interfaces yet

- Where: F `apps/desktop/src/main.ts:280–285,636–670,1399–1417`; F `App.tsx:590–626,9057–9066`; F `docs-window.ts:94–99`; D `logic.md:101–146`.
- Problem: the current normal native × hides immediately; quit stops the server then uses `app.exit`. The renderer is sandboxed and has no preload IPC. The proposal names correlation fields but leaves their types, transport, native interception, abortion acknowledgement, timeout and authoritative child-destruction evidence open. A boolean dirty guard cannot implement that interface. A late/unknown save or overwritten continuation can abandon a specified normal-path draft.
- Exact specification questions: **What selected shell↔owner mechanism prevents native close before any hide, server stop or teardown, and how does a matching refusal reach that shell? Which identity and terminal result do prepare/reply/abort/abort-ack/commit/child-closed carry, who validates them, and what is the deadline? Which authoritative event confirms destruction of this child rather than focus loss? How are same-room conversation switch, native child Return, normal quit, updater quit and Electron reload mapped into the selected arbiter?**
- Required resolution: freeze the contract register below, including native re-entry suppression and shutdown ordering. Normal native chat × remains protected even when the subsequent behavior is hide-to-tray. Q5=B does not exempt normal Electron quit/reload by implication; D explicitly requests proof of their interception. Any proposed exclusion beyond the exact Q5=B exceptions returns to Front/Sascha.
- Proving tests: R3–R8 and R15 below, including a real Mac native entry point. Fault injection may control replies or HTTP timing but must use actual producer and consumer implementations.
