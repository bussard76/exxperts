## Findings

1. **The union is 102, not 102 independently pinned target entries.** I independently verified 154 unique inventoried target paths have identical base and candidate entries at the stated version and lack both `resolved` and `integrity`. Against the retained records, 26 have the earlier fork-root or desktop alternatives; 90 match an upstream-ancestor history record; their union is 102, leaving 52. The `8b2a4d12a997958b7c288ae8bc47de0fb659295c` UI lock covers 86, including 10 of the earlier 26, so adds 76. All 52 remaining are marked dev and none are selected by the retained `.prod` query or UI sourcemap audit; those are classifications from the earlier current tree, not proof of a candidate pruned install or of irrelevance to building. The two removed candidate clean installs cannot be rehashed.

2. **The historical evidence is reproducible but bounded.** The initial UI lock is blob `9f2c29bf153053608005b3756c0a2bd0b434a374` at the stated commit, which is an ancestor of the base. I independently enumerated seven lock paths and 79 distinct path/blob pairs in available base ancestry and verified all 79 retained blob SHA-256s; two absent blobs correspond to deletion commits. I checked all 277 recorded historical matching entries against their actual Git source files for version, resolved presence and cache SRI, and spot-checked exact names, paths and URLs in the initial lock (including `@babel/helper-plugin-utils`, `mdast-util-mdxjs-esm` and `@types/ms`). No recorded same-name/version historical SRI conflicts with the observed cache. This is a bounded available-ancestry search, not proof of absence from every possible source; Git ancestry establishes lineage, not original target-path origin or an independent signature/authority. Public ref reachability reported by the researcher is a point-in-time observation; immutable commit/blob IDs identify the sources and objects should be retained for later audit.

3. **Current cached bytes are corroboration, not a clean candidate install.** I rehashed all 154 retained local cache archives against their SHA-512 SRI and SHA-256 inventory and checked each archive's top-level package name/version: 154 matched. The analysis, inventory, research JSON and two research scripts match their reported SHA-256s respectively `7cd8804611246671b65a3079c87878164337c310c4c0ff04cb03c837a07a3b5a`, `63f1422fcc5e2c5dbfc8674c5c7e3e6d110eb01b532607dea279cb5918d64b69`, `00ba0546de8d6bbdc32906f70935c0468fe101fc67375f1beba2eb70ffe280c5`, `081117a76644c074662f9f5cb29c465c21ac4ffafabd30ebec4332c16ee0e26f`, and `ab2abbd9a3dd900890b15449f5ffc1ef929c9a30a802f5057adcaf5d79a8e425`. The prior 1,911 installed regular-file comparisons were not independently repeated here. They exclude extra files, symlinks and modes and do not prove postinstall or native execution. `canvas` has an install script. The cache's own digest is not independent source authority; a historical same-identity SRI does not show what the missing path originally meant or what a removed installation fetched.

4. **Existing permission is narrower than the historical proposal.** The Controller clarification and R2 authorize a deterministic reconciliation using existing pinned upstream and fork root lock entries, preserving base entries, versions and integrity and failing on missing or conflicting metadata. The 20 fork-root alternatives are within the permitted source-lock set, but acceptance of each target mapping and full graph still needs the specified proof; no instruction explicitly fills these 20 missing target fields. The six desktop alternatives and 76 additional matches rely on locks outside that specified pair. Admitting them as source authority, even finitely and without fetching new registry metadata, is a new authority decision; same identity and matching SRI alone do not delegate it. R4's discussion of a possible finite reconciliation is not such a decision. The 52 have no matching pins within the combined bounded search and cannot be dismissed as dev-only.

## Minimum decision and verification package

Before seeking a decision, retain an immutable, hashed per-target table for all 154: candidate/base commit and blob, exact target path and entry, package name/version and flags, every proposed source commit/blob/lock path and source entry including URL and SRI, source-to-target rationale, conflicts and unresolved identities, cache archive SHA-256/SRI, observed usage and classification provenance. Include the original JSON and scripts, source Git objects, tool versions, search scope and missing-object/deletion errors, independent reproduction results, and an explicit 102/52 disposition. Preserve the actual decision text, trust basis, approved source and targets, residual risks, and independent Architect review. A URL, a self-computed digest, name/version alone, or current registry metadata is not authority.

For any subsequently authorized candidate, independently reproduce its exact lock from immutable inputs in two clean checkouts, verify all intended and unchanged entries and compare the resulting lock bytes. For each actual standalone graph and composed tip, perform a normal-lifecycle root `npm ci` with a fresh isolated cache and dev dependencies present, recording exact source lock, toolchain, config, target and logs. Retain the actual fetched archive bytes or an independently verifiable capture tied to the install and package path, not merely a later download or cache index. For each applicable target calculate the digest specified by its **actual candidate lock integrity**, compare it to both that SRI and the authorized source pin, and verify archive manifest identity; retain the bytes and per-path mapping. Prove the installer used those bytes at that path, including redirects and duplicate identities. Compare extracted archive entries to the installed tree with path-safe handling, file type, contents, links and executable modes; inventory additional, missing or modified files and attribute lifecycle outputs to the actual scripts, including native binaries. Audit the resulting built, pruned and packed artifacts and relevant licences, notices and size deltas. A digest equality for a tarball does not certify generated outputs, symlinks or platform behavior. Repeat per supported target or explicitly leave it incomplete; preserve independent actual graph/peer/optional/native and full acceptance checks including zero-exit `npm ls --all`, unchanged lock and the R4 floor guard.

Refuse acceptance on a missing/ambiguous target-to-source mapping, unauthorized source, differing SRI, identity or bytes, source conflict, missing captured install bytes, unaccounted files or lifecycle output, changed lock, unexpected path or dependency, incomplete platform evidence, or failed required gate. A missing historical record is not proof that no trusted source exists. Do not silently substitute the cache, a newly fetched registry response, omitted dev dependencies, a baseline-delta exception or a new waiver. The decision package must explicitly distinguish evidence for the 20 permitted-source candidates, the 82 other matched paths, and the 52 unresolved paths; none is already accepted.
