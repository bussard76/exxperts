## Findings and binding instructions

1. **R1 correction is not acceptance.** Compare `0280121` to its parent: it keeps exact RAW while switching, changes tasks per line and shows the RAW toolbar with task active state. This addresses the *design direction* of the three R1 failures, but inspection is not a Tester pass: R2 must independently reproduce all three and their regression tests, including exact file bytes after a saved RAW edit, no-typing round trip, and later RAW edit. R1's full gate failed; no subsequent gate result is claimed here.
2. **Ownership through external replacement needs explicit proof.** The current `contentSetterRef` and `discard` set `rawRef` to null while loading exact `next` or baseline into TipTap. That allows a later `getContent`/save to use serialized rich content instead of the exact new source even without a rich edit. Bind the invariant that latest accepted on-disk text remains exact until an actual rich edit, including clean polling, conflict Reload and discard, not just initial load and RAW typing. Exercise unsupported formatting through each path and a subsequent RAW edit/save. R2 should determine and report any actual defect; do not waive a loss as merely an edge case.
3. **Shared contracts and concurrency.** `rawRef` is the surface's exact-text source while non-null; pane `draft` is the visible mirror, not an independent authority. A save captures bytes and revision; completion advances the baseline to those bytes without replacing later edits. Conflict/error retains the latest draft, Reload adopts current server bytes, Keep mine uses current server revision and preserves later edits. Tests must cover RAW → Edit/Preview, Edit → RAW, save in flight, Keep mine in flight, Reload, failed save, dirty navigation, read-only and empty content through real producer and consumer. Prove mixed selected task lines, repeated cycle, indentation, caret active and disabled controls, both Edit checkbox directions and reload RAW. Use invented files only.
4. **Port is conditional, not a clean cherry-pick claim.** Five ordered source commits are `f999d7a`, `cc79d80`, `6213975`, `bc3743c`, `0280121`. A temporary index check against exact `cdc3d5c` found the first patch fails at `43-room-workspace.css:361`, because the Series 2 stylesheet lacks the fork preview CSS used as context. Applying all five non-CSS patches in order to that index succeeds; this is a textual check, not a build or behavioral compatibility proof. Reconcile each CSS hunk in order against Series 2, retain both geometry assertions, all tests and Series 2's own styling, and check the entire resulting diff for unintended fork-only content. Start only after independent R2 pass and gated fork integration and Controller direction; then Series 2 gets its own independent gate and composed gate. Do not port factory files, #12, or unrelated fork changes.
5. **Existing decisions remain in force.** Series 2 R2's image error-class identity, actual image/listing producer integration, policy matrix and dependency/lock obligations are unchanged. New source authority and Node floor are outside this task and remain blocked. No test suite or gate was run for this review.
