## Prefactoring

No broad refactoring. Extract the image-only seam and its existing error class once; Markdown imports or re-exports the same class and helper functions. Keep the guarded resolver and worker lifecycle as owners of their existing responsibilities. This removes the editor dependency without adding a second error identity or a new external flow.

## Binding Developer instructions

1. The later Controller clarifications override unresolved questions in the draft: `.xls` has an unsupported error state, no Open button and a refused direct open request; do not add a handler. Strengthen the parent workbook validator to require `typeof showGridLines === "boolean"` before emitting route success. Use a malformed child response through the actual route and verify the consumer displays a controlled error, and retain a legitimate boolean success case. This implements the already adopted schema, rather than changing it.
2. The shared contract at `~/controller-exxperts/specs/series-shared-contract.md` is the companion despite the draft's `.build/` shorthand. It governs both cuts. Preserve one `PersistentRoomWorkspaceMarkdownError` constructor identity, including errors translated by both Markdown and image helpers; the exact fork call signatures remain usable after the physical split. Do not expose raw unknown exception messages or absolute host paths through the route, even though the pinned helper's generic fallback can contain them.
3. The lock method is a feasible candidate, not proof that all required entries exist or resolve together. Deterministically derive the minimal closure from the two pinned lockfiles, preserve original resolved URLs, integrity and peer/optional/platform metadata, and retain unaffected base entries. In particular, the approved root `jsdom` change from base `29.1.1` to fork `26.1.0` necessarily changes its root lock entry and associated dependency closure; do not interpret preservation as requiring both versions at the same path. Resolve other path collisions only using compatible existing pinned entries and document each replacement or relocation and why it is needed. Never fabricate versions, integrity or licences, copy the fork lock wholesale, run `npm install`, or ignore lifecycle scripts. If the required complete compatible closure cannot be assembled from those entries, stop and return the specific missing package/path or peer conflict to the Controller; do not silently expand dependency approval.
4. Prove the candidate lock in a clean checkout using the specified normal-lifecycle `npm ci` with approved browser-download suppression, verify repeatable lock output and dependency tree including relevant peers, optional and platform packages, then audit actual build, bundle, pruned and packed artifacts and licence/NOTICE sources. The named jsdom consumers and supported available platforms need regression evidence; explicitly report unverified platforms. A successful install on one platform does not alone establish all native/optional closures, licences or shipped bytes. Any missing evidence remains an acceptance failure, not an assumed pass.
5. Maintain the public route/browser acceptance matrix and real producer-to-consumer checks, including in-flight HTML revocation for both forms, all retained extension rows, empty/error states, current policy, paired refusal, genuine frames, and fake-only OS dispatch. A malformed child must be rejected by the parent before a successful response; browser checks should demonstrate the resulting error rather than expect malformed successful data to reach its consumer. Do not weaken existing tests. Keep factory, process, design, ADR and review files out of the actual upstream contribution.
