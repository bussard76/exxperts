## Prefactoring

None established. Keep any proven level-1 solution within the existing capacity measurement implementation and existing command. Do not introduce a shared module or dependency just to test it. A controlled test adapter must be private and isolated, and must not bypass the real parsing and verdict path.

## Findings

1. **Ownership and time identity are not specified (design blocker).** A directory name or currently live PID does not bind an identified gate/worker to this project and a process incarnation; the common full-gate lock also spans projects. The spec must identify exact authoritative producers, root fields and verifiable lifecycle for both runners and both host placements. If this needs gate/worker producers to emit a new durable or cross-process identity record, that is a new contract/data flow: return level 3 with options and a recommendation for Sascha, not a level-1 implementation. If an existing, reliable source suffices, demonstrate it and specify exactly how. Conservative unknown handling may leave some real descendants counted foreign; do not claim complete attribution in that case.
2. **Failure behavior and test seam are design-relevant.** The current sampler drops unreadable cwd rows and its transport masks failures as empty output. Specify the safe behavior for unknown process CPU and whole-probe failure, and the exact controlled injection without reaching real state or adding an unsafe production input. For PID reuse, define identity as at least host/boot, PID and kernel start time, require verified parent relationships during the sampling interval, and treat any race that prevents proof as unknown. Start time alone does not establish project ownership.
3. **Outside-in and concurrency evidence are incomplete.** No `design/TCAPACITY-ATTRIBUTION/`, interface definition or logic diagram was found. This is a Controller bug fix, not a UI feature; a compact input-to-verdict diagram and the exact existing command and sample are appropriate outside-in evidence. The dispatch does not identify parallel implementation tasks. If split, record dependencies and freeze the producer/consumer fields and failure semantics before parallel work, with a test crossing the actual producer and consumer.
