## Findings requiring specification changes

### 1. Node failure equality does not establish the declared minimum

- Where: #22, Goal, step 3, Done when and Abort; root `package.json` engines; Experiment C `summary.txt` Node-floor result.
- Problem: the goal says the minimum is proven, but step 3 accepts baseline and series showing the same result, and Abort only names a series failure where baseline passes. After fixing the missing-runtime-declarations setup, both could still fail build/typecheck/smokes identically at Node `20.6.0`. That establishes no additional regression; it does not prove the advertised floor works. #22 expressly tolerates the baseline lock gaps and `npm ls` defect, but does not say whether an unrelated Node failure also counts as success. A Developer cannot decide that extension of acceptance.
- Required clarification: require successful runtime build, UI/scripts typechecks and applicable Series 2 flows at the advertised minimum and pinned Node 22; record baseline failures separately. If baseline and series still fail identically, mark the floor **unproven**, retain exact diagnostics and return to the Controller without changing engines, product code, dependencies or checks. If the intended deliverable is only a regression comparison, state that explicitly and do not report the minimum as proven. No new Sascha decision is needed to state an honest incomplete result.
- Proving evidence: a per-ref/per-Node matrix with exact Node/npm versions, commands, exit codes, full output and diagnostic differences, including the runtime build. Equal nonzero exits alone cannot be a pass. The old 235 missing-declaration diagnostics are inconclusive and cannot supply this evidence.

### 2. The targeted-smoke comparison has no defined baseline counterpart

- Where: #22 step 3's "targeted series smokes" and "Baseline and series must show the same result"; revised Series 2 acceptance matrix; `apps/web-server/scripts/workspace-markdown-images-ui-smoke.ts:18` at the reviewed tip.
- Problem: the new editor-specific smoke files and routes do not exist at upstream `461e6485`. The ticket does not name the smoke set, distinguish common baseline checks from series-only checks, or specify the UI artifact prerequisite. The browser smoke exits 0 when Chromium is absent, so exit equality can also hide an unexercised producer/consumer flow. These ambiguities directly change what qualifies as done, rather than merely how a command is spelled.
- Required clarification: name the exact common baseline checks and series-only smoke list, build the runtime first under each selected Node, and build the UI artifact before browser checks. Compare common diagnostics/flows on both refs; require the series-only smokes to execute and pass on the series at both Node versions, with baseline applicability explicitly marked. Do not copy new product code into baseline to create a counterpart. State that browser skips are incomplete evidence and that all spawned server/tsx/npm processes use the selected Node, not the host default.
- Suggested bounded list for the Controller to adopt: existing series `composer-text-insertion-smoke.ts`, `persistent-room-workspace-files-smoke.ts`, `persistent-room-workspace-markdown-files-smoke.ts`, `workspace-markdown-images-smoke.ts`, `workspace-markdown-images-ui-smoke.ts` and `workspace-markdown-notices-smoke.ts`; retain relevant existing policy/remote checks from the approved acceptance matrix. Later RAW/task smokes apply only after the separately authorized addendum port. Choosing the final check matrix belongs in the task, not in an unrecorded Developer assumption.
- Proving evidence: no missing file, omitted test, setup failure or Chromium skip reported as a success; actual route -> editor -> save/image/conflict/navigation execution with invented files, and a reproducible list of baseline comparisons and series-only results. This review does not request a full gate.

Preserve exact peer compatibility and required optional/platform behavior. No new direct package or arbitrary registry-source exception follows. The prior deterministic reconciliation approval is available; measurement-only authorization for `npm install --package-lock-only` in Experiment C is not general permission to run it on the contribution branch.
2. **Keep the baseline exception finite.** Read existing `baseline-ls.log` and `series2-clean-ls.log`: both have `ELSPROBLEMS`, invalid root `@types/node@20.19.40` for runtime `ai`, `agent`, `coding-agent` requirements `^24.3.0`. Additional invalid, missing, extraneous or peer problems are new errors, even with the same exit code. A genuinely clean `npm ls` is not a regression, but must not result from hiding packages or weakening checks. Old zero-exit-`npm ls` and perfect-lock requirements are superseded only to the extent expressly stated by Sascha in #22; checks for newly added dependencies remain intact.
3. **Clean installation and signatures remain required.** Final clean `npm ci` and `npm audit signatures` must exit 0. Normal lifecycle stays enabled; the approved browser-download opt-out does not waive executing browser checks with available Chromium. Experiment C's Node `22.23.4`/npm `10.9.9` run reports install 0, ls 1, signatures 0, 871 verified signatures and 165 attestations for Series 2; these are read historical evidence, not this review's rerun or final branch proof. Record absent signatures/attestations explicitly; signature success is not a complete attestation claim. Retain upstream's existing SheetJS URL; do not introduce another nonregistry source or contact real services/data as a workaround.
4. **Audit applicable licences and shipped notices.** List every new package/path/version, including transitive, peer and optional additions and whether installed, pruned or bundled. Use actual package licence/NOTICE files and built/packed contents to determine attribution; retain applicable upstream notices and Omnigent commit `da7555532be25cd127a3cdee8bf8bb32071932fb`, Databricks attribution and source headers. The existing `NOTICE` and `workspace-markdown-notices-smoke.ts` check actual bundled licence text and package inclusion, so preserve their assertions and rerun against the final graph. Registry MIT fields do not replace that check, shipped-size accounting or the approved packaging obligations. `buffers@0.1.1` is a Series 1 concern, absent from these 63 additions; do not add it, repair it or hold Series 2 for that other task. 5. **Abort with evidence.** Stop on a new dependency-tree problem, >160 gaps, any newly incomplete added entry, integrity/signature/clean-install failure, unrelated lock mutation, or a series regression against baseline. Preserve exact output and the candidate inputs. The clarification requested in finding 1 must also define the common-failure floor outcome. Do not repair upstream defects, relax a smoke/assertion, change Node engines, suppress lifecycle/peer/platform checks, import Series 1 dependencies or create a new policy decision to force success.
