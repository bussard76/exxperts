Check exact host and project worktree as well as terminal and incarnation; unavailable or inconsistent information is unknown.
- The environment value is inherited process metadata, not an authenticated ownership credential. A shell or another project launched under the terminal can inherit it; another same-user process can copy it. PID/PPID/start ticks eliminate some reuse and ancestry races but cannot authenticate the value or decide what project a gate belongs to. A common full-gate lock holder is not project-specific; slot files contain PIDs without start identities and may be missing. An unrelated process can forge a matching handle, and a foreign gate can inherit one. Empty, removed, inaccessible, conflicting or duplicate handle metadata establishes nothing. Never exempt solely on a handle, cwd substring, process name, lock or unverified slot PID.

## Private probe and classifier contract

Within `capacity.mjs` retain the existing one-host `onHost` execution and existing pressure measurements. A precise private wire format is newline-delimited JSON, one header `{ "kind":"header", "version":1, "bootId":"<linux boot id>" }`, followed by zero or more `{ "kind":"process", "pid":123, "ppid":45, "startTicks":"678", "pcpu":12.3, "handle":"term_example" }` rows, and `{ "kind":"end", "version":1, "count":N, "bootId":"<same id>" }`. `handle` is either the single exact `ORCA_TERMINAL_HANDLE` value or null; never transmit other environment values, arguments, cwd or command names. Ancestor-only rows have `pcpu:null`; every one of the top-30 `ps` candidates has finite nonnegative `pcpu` and is present exactly once. Use the existing >=5% cutoff and strict unrounded foreign `> threads/4` decision. Capture all needed ancestors, not just the top 30; bound rows and traversal depth, and report truncation as unknown rather than proving ownership. Preserve separate PSI, load, memory and queue data and output schema; framing may coexist with their existing fixed-key lines if unambiguous. This is an internal implementation interface, not a new CLI option or published protocol.

On the sampled host use `/proc/sys/kernel/random/boot_id` and `/proc/<pid>/stat` fields 4 (PPID) and 22 (start ticks); parse stat around its final `)` correctly. For each PID obtain stat before and after selectively reading only the named NUL-delimited environment entry, and require the same PID, PPID and start ticks; reject duplicates or malformed handle records. Match each child to a sampled parent whose start tick is no later than the child's; re-read and validate each link and root during the bounded capture. Reused, missing, reparented, inaccessible, contradictory or unverified links are unknown. Two validated reads cannot make the capture atomic or authenticate the handle: do not claim otherwise. A root is usable only if a separate authoritative source proves its project and host, PID/start/boot identity, and active terminal incarnation. Multiple independent roots are allowed, without double counting. A confirmed foreign gate in an otherwise owned chain terminates project attribution for its subtree; if gate project cannot be established, treat it as unknown.

Local and remote use the same script on the **sampled** host, not the Controller host, and the Controller associates its header with the configured target and matching remote Orca environment; never compare PIDs across hosts or boots. SSH error, missing/duplicate header or end marker, invalid counts, malformed CPU, interrupted output, missing boot identity, unsupported `/proc` or failed `ps` means process sample unavailable: return suite `wait` with a generic note, do not infer zero foreign or generate a quiet calibration period. Known sampled CPU with an unverifiable row counts foreign, including unreadable cwd or environment and vanished ancestry. Retain existing read-only admission and PSI/gate-slot rules; prevent sample failure from accidentally raising calibrated caps. Never print raw probe output, boot ID, handles, PIDs, paths, environments or command lines in verdict, journal or errors.
