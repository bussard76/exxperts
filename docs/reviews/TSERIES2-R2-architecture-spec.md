## Findings and binding Developer instructions

1. **One image class and producer.** The Series 2 draft lists the fork's original combined Markdown/image file, while the authoritative shared contract moves image exports and `PersistentRoomWorkspaceMarkdownError` to `persistent-room-workspace-image.ts`. Implement that shared path on both standalone branches; the Markdown helper imports or re-exports the same class object, and route error handling uses that identity. Do not define a second class, route or image implementation. Preserve fork signatures, messages, statuses, bytes, headers and authorization, including `currentRevision` handling. The shared contract's explicit split resolves the location difference; it is not a second wire contract.
2. **Lock reconciliation is conditional, not a claimed result.** The later Controller clarification supersedes each draft's unresolved `npm install`/generation question. A local deterministic script may select the needed upstream and fork lock entries, preserving base entries and resolved versions, integrity and peer/optional/platform metadata, and update the relevant workspace manifest entry for the approved direct dependencies. It must construct the complete path-resolved dependency closure and fail/report an incompatible collision or missing required entry rather than invent metadata, silently replace base entries, or copy the fork lock wholesale. The method is feasible from the two version-3 lockfiles if such a compatible closure exists; this review has not proved that it does. Repeat generation from the same inputs and compare the result, then validate a clean checkout with normal-lifecycle `npm ci`, dependency-tree validation, actual build/pack and licence/NOTICE audit. Do not use `npm install` or suppress lifecycle scripts. Record platform/optional coverage and any unverified platforms; a successful install on one platform alone does not prove every platform closure. If the inputs cannot produce a complete compatible lock, stop and report the concrete missing or conflicting entry for a Controller decision. Audit actual shipped artifacts and applicable Omnigent attribution; inventory is preliminary only.
3. **Composition and tests are gates, not assumptions.** Each branch must build and pass its own acceptance from the pinned base without the other. The later composed-tip gate must exercise the real Series 1 listing/image producer with the actual Series 2 editor, including local and blocked external images, conflict/Keep mine, failed-save retention, dirty navigation, tabs/drag and both acceptance sets. Browser skips or separate standalone passes cannot substitute. If work is split further, name owners and dependencies before dispatch. Preserve the original local and paired authorization matrix and public/browser checks; do not weaken existing tests. Sascha's original human image/edit/diff acceptance remains separate.
4. **Scope of the later clarifications.** Hide the unusable `.xls` Open action in Series 1 and test route refusal; do not add `.xls` support. Strengthen the spreadsheet parent validator to require boolean `showGridLines`, and test rejection of malformed output end to end. These implement the recorded decisions and accepted schema; neither requires a new level-3 decision. Any additional contract or behavior change must return for classification.

The prior review's remaining binding details are represented in the revised route, editor, dependency and acceptance matrices. No implementation, test suites or gate commands were run. The pre-existing modified `package-lock.json` was left untouched.
