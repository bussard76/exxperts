## Finding: stage identity is not dependency byte provenance

R2 steps 1, 3 and 4 require original input digests, exact provenance, and comparison of each actual bundle input against the installed graph and lock; its notice policy additionally requires verified original texts. At the reviewed seam neither lockfile is in the release archive. More fundamentally, a lock entry's registry/CDN integrity is a digest of the *package tarball*, not a digest of the extracted, lifecycle-processed, dereferenced and generically pruned stage. The contents and names left in the stage cannot reconstruct omitted bytes or prove which tarball produced them. A self-computed inventory records the presented bytes and detects later mutation; it cannot authenticate their prior origin. Hashing those same bytes again, keeping manifests or naming a compiler metafile likewise does not repair this missing independent comparison. Different package contents can retain the same manifest and pass the existing checker.

**Conditional answer:** exact **retained input-file byte identity** can be checked offline from the stage against a complete, independently sourced and reviewed, version/target/location-specific expected inventory pinned in the packaging implementation, with explicit handling of each authorized transformation. It needs no checkout, global node_modules, network, extra runtime parameter or archive mutation. This only establishes equality to that inventory and the chain by which the inventory was independently derived; it does not reproduce npm tarball SRI from a pruned tree or establish absent source/notice completeness. No such complete verified inventory or original notice evidence is demonstrated by these frozen revisions. Thus R2 as written is not yet executable as a provenance guarantee and its original notice requirement remains an acceptance blocker, not optional debt.

## Bounded options

1. **Preferred within the current interface, if evidence and size permit:** independently obtain and verify each exact original locked package tarball against its pinned SRI in a separately authorized research process; derive a reproducible inventory mapping target, full stage-relative location, package name/version, retained file path and SHA-256 after documented deterministic authorized lifecycle/patch/prune steps. Review and pin that inventory as private data at the existing packaging seam, alongside separately verified exact missing notice texts and their source/version/digest. At execution, before writes, enumerate all compiler inputs and required retained resources/notice files, require exact path/version/target/digest matches, reject missing, unexpected, foreign or ambiguous entries and then record actual input and generated-output digests separately. Treat optional/native variants explicitly; do not compare an installed file directly to a tarball SRI or bless a file merely because its self-derived digest is stable. Deterministic transformation evidence is needed for each modified file; unavailable or nondeterministic inputs fail closed. Confirm data volume, maintenance and compiler-input coverage before selecting this approach. Compiler version/flags and output checks still require their own evidence; hashes do not prove semantic or legal completeness. The inventory must itself be independently reviewed and pinned, not generated at runtime from the same stage.
2. **Producer evidence:** retain a separately authenticated producer attestation or file inventory bound to exact source revision, target, lock digest, build transformations and archive digest, with independent review/trust anchor, and pass it to desktop packaging. This changes the producer/consumer contract and data flow and needs a new architecture decision; a sidecar generated by the same untrusted producer alone is only another self-report. It also does not supply notices already omitted unless those are separately verified and supplied.
3. **Independent trusted full source inputs:** provide reviewed exact package tarballs/source and notices as a distinct offline input and verify locked SRI before applying documented transformations. This is a new input/contract and may add storage and target-specific build complexity; classify and approve it first. Never recover by silently searching a checkout, global install, network or modifying the shared release archive.

Do not weaken exact provenance, infer a license from a manifest label, fabricate missing upstream texts, or reclassify the notice requirement. Any change to shared release packaging or the approved self-contained private-stage contract is outside the present level-1 authorization. If verification or required source redistribution cannot be expressed in the selected scope, stop and escalate.

Disposable fixture and copied checker were removed. Future public-seam tests must include complete expected inventory positive, changed bytes under unchanged manifest, missing and extra/foreign/incorrectly located input, wrong target/version, wrong pinned inventory or digest, and missing/altered notice; all failures must occur before stage mutation. Also demonstrate the legitimate target-specific lifecycle-transformed case against independently approved expected bytes, and verify archive/source copies remain unchanged. These are required future checks, not results claimed here.
