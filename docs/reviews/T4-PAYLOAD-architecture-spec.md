## Findings

### F1 — [major, design-relevant] Server-only exclusivity is unsafe in the shared release installation

- Where: research design steps 1 and 3 (`docs/reviews/T4-PAYLOAD-research.md:125` and `:127`); frozen `scripts/bundle-release.mjs:290` bundles inside the installed root before staging; `apps/desktop/scripts/package.mjs:166` distinguishes the later desktop-only trim. `runtime/packages/coding-agent/src/core/settings-manager.ts:5` and `auth-storage.ts:19` import `proper-lockfile`.
- Problem: the proposed 187 “ExcelJS-exclusive” locations are exclusive only relative to the other **server file-package roots**. The proposed transform runs in the installation subsequently copied into the CLI archive. There, `proper-lockfile/lib/lockfile.js:4` still requires `graceful-fs`, one of those 187 locations. Preserving only its manifest/notices deletes its executable entry. The compiled server's copy cannot serve the separately loaded CLI. The existing manifest/version and relative-TypeScript checks do not catch this missing JavaScript.
- Evidence: an independent graph walk from all other root production/optional dependencies intersects that deletion set at **28 package locations**, including graceful-fs, readable-stream, buffer-crc32, end-of-stream, safe-buffer and side-channel dependencies. This is a preservation obligation, not an assertion that every declared dependency executes. A disposable four-package fixture using actual proper-lockfile/graceful-fs/retry/signal-exit code returned `typeof require("proper-lockfile").lockSync === "function"`; reducing only graceful-fs to manifest/notices then failed with `MODULE_NOT_FOUND` for its main. Each subprocess used `--no-global-search-paths` and empty NODE_PATH/NODE_OPTIONS. No actual product installation was pruned.
- Required correction: explicitly separate the desktop-only code-deletion policy from source development, packed dependency installs and the shared release/archive tree. Recommended minimum: perform the complete private transform/deletion only on the already staged desktop `app/` copy through its existing pruning interface, retaining its synchronous public interface and using already available esbuild. Keep the source installation and archive CLI graph untouched. If Controller instead selects a shared-install transform, derive retention from **every consumer of that artifact**, including CLI/runtime and helpers, and revise the budget before authorization.
- Proving tests: through public packaging/pruning entry points, use invented staged trees to prove desktop transformation while the archive/source copies remain byte-identical; include a real public proper-lockfile import in the archive control. Add a shared-package fixture and ensure its entry still executes after trimming. Independent installed/archive CLI checks must exercise settings/auth initialization with invented state and fake services, and installed/pruned desktop consumers must still work.
- If skipped: an archive can retain plausible package manifests and pass the current metadata checks while its CLI fails at module loading. This conflicts with the proposal's preservation requirement, so the exact supplied design is `change-spec`, not merely test debt.

## Minimal safe design and binding precision

1. **Bound the output owner.** Controller records the staged-desktop-only choice, or supplies a corrected complete shared-artifact retention plan for review. Keep changes private to existing packaging scripts; no new module export, runtime bridge, dependency, parser or public option is needed. Generate/validate in memory before deleting files, and do not mutate the original registry installation during normal server builds. A synchronous existing pruning interface must not silently become asynchronous.
2. **Use the exact public Node entry.** Resolve ExcelJS 4.4.0 physically inside the selected installed/staged root; use existing esbuild, full `require("exceljs")`, CJS, Node platform, an explicit target compatible with the unchanged policy, metafile and legal-comment preservation. Preserve the manifest, package name/version and Workbook/ModelContainer/stream/enums surface and default ESM interop. No browser-distribution substitution, private `lib/doc/workbook` import or Workbook shim. The manifest also advertises `browser: "./dist/exceljs.min.js"`; preserve that target if retaining the claim of unchanged advertised runtime entry points, or have Controller explicitly scope the promise to the supported Node consumer and prove no other artifact consumes that path. Do not call a deleted advertised target a fully preserved package surface.
3. **Derive retention from the correct artifact's consumers.** For desktop, preserve every other shipped root and its location-resolved closure, plus actual retained helpers/children. Shared packages remain complete for other consumers even when ExcelJS embeds their code. Preserve all 252 original manifests and named notices, rather than falsifying closure declarations; any newly shared input stays. Use original installed inputs for notice/graph collection before removal. New dynamic/own-location sites, unresolved imports, foreign-root realpaths, unknown versions or changed entry shape must fail before deletion; warning-free esbuild/metafile output is necessary but insufficient.
4. **Preserve owned parser resolution without adding a parser.** Keep ExcelJS-owned saxes 5.0.1 at its actual nested location, its manifest and `saxes.js`, plus xmlchars 2.2.0 and the xml/xmlns files it requires. Root saxes 6.0.0 cannot substitute. Source correction: neither frozen c780e72's shelf child nor inspected 1bb52ef's child currently contains the research's described `excelRequire`/saxes calls; c780e72 has no ExcelJS import, and 1bb52ef loads ordinary ExcelJS before still returning unavailable. Package checks and the narrow approved import-audit exception exist, but a future direct child parser is not an implemented fact. Retain closure conservatively; do not resurrect the superseded XML-validator design to justify it.
5. **Collect complete attribution before reduction.** Retain existing named notices and add a provenance-bearing ExcelJS sidecar covering the actual inlined input paths, package locations/versions, README/source notices and shared embedded code. Preserve any required original source notices/files as applicable; do not assume one generated text universally substitutes for source obligations. Record original lock integrity separately from transformed output/input digests. Keeping an unchanged manifest does not attest registry-identical bytes, license completeness or functioning code. Keep existing SBOM/lock checks and add artifact evidence rather than making manifest-only directories count as runtime proof.
6. **Keep non-Excel assets intact.** Register approved child SheetJS ownership in FILE_PACKAGES once its actual consumer is implemented; retain its full generic-pruned 18-file package, SSF/codepage surfaces and cpexcel assets. Preserve the existing runtime spreadsheet-preview consumer. Leave jsdom/docx-preview/JSZip resources and other consumers intact, including jsdom's generated interfaces, `js-globals.json`, XHR worker, nested parse5/entities and encoding tables. Preserve pdfjs legacy build/worker, CMaps, standard fonts, wasm and ICC resources/notices; retaining them does not prove the child supplies correct URLs. Preserve canvas's target addon, Koffi's loader/all currently retained native targets and vendor/cnoke notices, Playwright driver/data and recheck/synckit workers/native selection. Only the existing recheck-jar exclusion applies.
7. **Keep ordinary source and installed contracts distinct.** Development uses original dependencies. Test packed tarball installation as a dependency outside a checkout separately from the release root's lock-driven `npm ci --omit=dev`. Test the generated main and resources again in the actual pruned artifact through real approved consumers. No NODE_PATH, source tree, parent installation, global package or browser CDN fallback; record physical resolved paths and deliberately poison outside-root packages in fixture negatives.
