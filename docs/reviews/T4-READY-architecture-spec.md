## Findings

### F1 — Design-relevant: affirmative local authorization and opener completion remain unspecified

`T4-ADR-spec.md` leaves O1/O8/O9 open; `T4-spec-ready.md:26,30,36` likewise delegates locality, platform behavior, shared-server treatment and path replacement mitigation without selecting them. These affect the approved host side effect and cannot be left to independently working producers/consumers.

Code evidence: `remote-routes.ts:356–366` returns before classification when no device is attached. `request-checks.ts:119` delegates to an optional shared-server edge before the normal proxy, address and token checks. Its ordinary HTTP origin check at lines 222–225 accepts any localhost port, and its folder chooser helper at lines 396–402 accepts absent origin. Neither helper plus a `local` route is a complete authorization contract for this action. `server-hooks.ts` already provides `isSharedServer()`; no new deployment mechanism is necessary.

**Controller/Architect resolution recommended within ADR-0003:**

1. Adopt the proposed `POST /api/persistent-agents/:id/workspace-open`, JSON `{ conversationId: string, path: string }`, and `X-Exxperts-Local-Action: open-workspace-file`. Require nonempty strings and workspace-relative input; accept no executable, application override, URL or absolute target. Keep normal token/session authentication.
2. Deny shared-server requests, including administrators; deny tunnel-tagged sockets and both paired capabilities. This follows the existing definition that a shared server is no person's computer. Require a trusted socket loopback address and the supported local Host; reject proxy metadata. Require an exact app Origin, including the existing Vite origins only in development, and the intent header. Reject absent/`null`/foreign origins for this browser action. A CLI-without-Origin capability is not required. Reuse the `isAppOrigin` semantics rather than the broad localhost predicate; do not trust forwarding headers for locality. Test local browser and Electron-origin shapes against this same contract.
3. Resolve a usable room and the current effective conversation policy, require workspace tools and selected `read`, then resolve via `resolvePersistentRoomWorkspaceExistingFile` and the agreed type allowlist. Repeat effective authorization and target resolution immediately before dispatch; compare the initial and final target identity/stat and refuse detected replacement. Never reuse a cached absolute path or fall back after a guard failure.
4. Record the remaining pathname race explicitly: an external application opens a pathname later, so repeated checks cannot make that consumption atomic. Do not introduce copies, a durable handoff store or a new protocol to claim otherwise. The ADR already identifies this limitation; document concrete mitigation and Controller review rather than automatically reopening option A. Escalate only if a concrete exploit requires protection beyond the accepted workspace model or a changed target-handoff design.
5. Retain the proposed internal `openWorkspacePreviewFile(guardedAbsolutePath: string): Promise<void>` seam with test injection at its actual owning server module. For each enabled platform, specify the fixed mechanism, exact argv/file encoding, acknowledgement event, deadline, missing-association/unavailable/headless behavior and errors. A process `spawn` event alone must not mean success if a later observable exit reports failure. Fixed executables and non-shell argument arrays are binding; do not use `cmd /c start` or another shell string. Return proposed `202 { accepted: true }` only at the defined acknowledgement; map failures to the approved sentence without stderr or host paths. No automatic retry.

These are bounded implementation contracts for the Controller to adopt, not additional Sascha decisions made by this review. A platform omission that removes required product support, or enabling OS opening on shared/nonlocal deployments, would require an actual scope decision. Missing association/headless failure itself is an expected error state, not grounds to defer the feature.

### F2 — Design-relevant: select one buildable parser-to-display flow for Word and PDF

`T4-ADR-spec.md`'s preview alternatives and O2/O3/O7 and `T4-spec-ready.md:23–25,31,55` do not specify how chosen producers reach consumers. This changes isolation and asset loading, not merely field spelling. Directly displaying docx-preview output in a scripted frame would violate the unchanged document-HTML rule; main-page parsing would violate the parsing rule.

Code evidence: `persistent-room-shelf-reading.ts:198–262` forks a child with timeout, heap cap and IPC; its public text parser returns text, not styled Word. `shelf-parse-worker.mjs:251–284` extracts only Word text, while its existing `pdf-raster` mode returns page images. `scripts/bundle-server.mjs` already ships `jsdom`, `pdfjs-dist` and `@napi-rs/canvas`; `FILE_PACKAGES` currently contains `qrcode-terminal` and `jszip`. A native canvas dependency is already optional, so a page-image approach must surface its absence. The old draft's in-process XLSX parse and style-overriding Word CSS cannot be treated as acceptance evidence.

**Recommended smallest compliant direction:** ExcelJS in the existing child; Word rendering in that child using the probed docx-preview/jsdom approach, returning static HTML/styles with embedded data images to `sandbox=""`; PDF using the existing isolated raster path and page-image consumer where it meets the required look. The Controller may choose an isolated browser PDF renderer instead, but must then specify its loader, worker assets and message protocol. Do not select multiple alternatives for the Developer to reconcile later.

For the chosen flow, record input/output, MIME and response headers, embedded asset representation, loading/error delivery, and no-network behavior for each applicable process/frame. Child-generated `blob:nodedata:` image URLs are not browser-transferable; the probe's data-image approach needs the correct DOM `Blob`/`FileReader` context. Remove or neutralize external navigation as well as images/subresources; an empty sandbox alone does not block a link from navigating its own frame. Direct navigation to returned document bytes must retain containment. Preserve document styles without inheriting app table/theme overrides.

Record exact dependency versions and consumers, licence/advisory review and packaged worker assets. ExcelJS is a product choice, not blanket approval for unnamed transitive runtime loading or a formatter dependency. Installed `jsdom` is already a shipped external; do not add a duplicate `FILE_PACKAGES` entry by rote. No new dependency is approved by this review while the selected flow is unresolved. Browser proof with invented fixtures belongs to the later implementation checks; this review does not require another fake or a real-file probe before the spec can pass.

### F3 — Design-relevant: freeze preview schemas, format scope and resource failure behavior

`T4-spec-ready.md:23–26,36–38` explicitly leaves the shared representation, statuses, limits and exact type set open. `T4-ADR-spec.md` proposes sheet rows/cells but leaves coordinate/style semantics, border fields, empty cases and number formats unresolved. A producer cannot know what to serialize and a consumer cannot know how to display required fills, fonts, borders, widths and calculated values. The draft branch's sheet cap also contradicts reaching every sheet.

**Required revision, owned by Controller with Architect review:**

- Adopt one route table: preview GET query `conversationId`/`path`, `read` classification, exact kind/MIME per supported format, error `{ code, error }`, status mapping and safe copy. Keep #5's `workspace-image` query, byte limit and headers unchanged. The proposed preview statuses 400/403/404/413/415/422 are reasonable defaults; reconcile guard-specific errors without exposing absolute paths. An opening refusal from an earlier hook may have another payload, so the UI must use the approved opening-failure sentence for every failed open action.
- Fix the Excel worker/HTTP schema: sheet identity and order, row/column coordinates and dimensions, sparse/empty representation, display text, validated style fields and units, column widths, border sides/styles/colors, and any merge behavior needed for the named basic look. Define how required number/date/percentage formats become text; the required stored-result fixture must be formatted, not merely `.text` from ExcelJS. Select an existing formatter or bounded implementation first; name any added package for review.
- Distinguish preview success, old-`.doc` error-only tabs, unsupported clicks and OS-open eligibility in one exact extension table. `.doc` is an error message, not automatic permission to open it. Prefer the established #5 image set for preview instead of a second competing image contract, with its SVG containment retained. Do not silently enable SVG or legacy Office in the OS opener merely because the image route or old draft recognizes them. Support beyond proven workbook formats needs evidence; silently dropping draft `.xls`/`.xlsm` behavior as a resolution of the issue's generic “Excel” scope needs Controller reconciliation and, if a real scope reduction, Sascha's decision.
- Set finite input, worker duration/memory, expanded-output and decoded-image/page limits, and active parse concurrency. Existing 25 MiB shelf input, 30-second parse timeout and 512 MiB JS heap are starting defaults for Controller review, not protection against all decompression/native allocations. Preserve #5's 20 MiB image limit. Reject an over-budget document with a plain state rather than silently omitting sheets/rows/pages. Every sheet of an accepted workbook must remain reachable. Technical rejection bounds are supported by the required “too large” state; only a changed promise such as successful partial display with inaccessible sheets needs a product scope decision.

The acceptance table already asks for actual producer output consumed by the UI. Keep that integrated test and name its owner and dependencies in the build task. If work is parallel, freeze the route/worker/schema table first; the browser integration test depends on the server/parser producer and real UI consumer. Do not give each worker permission to choose its own shapes. Sequential implementation needs no extra worker or shared-contract framework.

## Precision-only instructions and bounded defaults

These do not independently justify another design round once F1–F3 are resolved:

- Correct `T4-spec-ready.md:8,10`: ADR-0003 is now accepted. Preserve #5 integration, independent spec pass, later Tester review and level-3 conformance as separate gates.
- Use tab identity scoped by room, conversation and canonical workspace-relative path. Keep state local to the UI; no new durable preview cache or reuse of the shelf's reading-cache store is required. Ignore responses for abandoned contexts, and clear file views on room/conversation/person changes. Reopening activates one tab. Unknown/unsupported tree files do nothing; `.doc` opens its one-sentence error state as required.
- Existing `App.tsx:544–600` already supplies save/discard/stay and failed-save cancellation. Apply it to activating an existing preview as well as adding one, dirty-tab close and navigation that would lose drafts. Background close preserves active selection. Retain the existing non-workspace pane and Escape behavior rather than introducing another product interaction. Test failed save before the pending action runs.
- Recommend the explicit issue/design labels (`Open in Word`, `Open in Excel`, `Open PDF`, `Open in default app`) without default-program discovery. The OS association remains authoritative. The issue explicitly leaves the labeling approach open, so have the Controller record this bounded selection; do not represent it as Sascha's additional approval.
- Recommend no watcher, polling or automatic refresh after an external edit. Retain the loaded preview until its tab is closed and the file opened again; that new open fetches the current file under current policy. Reclicking an existing tab only activates it. This is the smallest interpretation of the stated no-refresh assumption and adds no new store or UI control. Controller should record it; escalate only if automatic refresh is actually required.
- Recommend stored cached values without recalculation; for a missing formula cache, display an unavailable-value marker with a plain explanation, never the formula or an invented zero. A stale cached result remains the stored result. Controller can fix this error/empty-state copy within the existing assumption; recalculation or a promise of fresh results would be new product scope.
- Use one-sentence state copy, including `Save this old .doc file as .docx to preview it here.` Loading and an empty sheet need explicit visible text; exact ordinary state wording is implementation precision. Numeric limits must come from the revised contract, not the drawing's unconfirmed sample numbers.
- Hide the open action on paired/shared contexts and omit it in Markdown. The existing client-context hook initially defaults to local; gate this new affordance on a successful local-context answer rather than changing unrelated controls. Server refusal remains authoritative. No extra paired explanatory card is required by the signed flow.

## Decisions, debt and return gate

The open-action architecture choice and Figma exception are closed. F1–F3 need concrete Controller/Architect selections in a revised build spec, not another broad question to Sascha. Only an actual requirement reduction (for example, excluding a promised workbook/platform), a new permission to launch from shared/nonlocal contexts, a relaxed document sandbox, or a different target-handoff flow calls for a new product/level-3 decision. If a compliant renderer cannot meet the named basic Word/Excel appearance, report that proven tradeoff with options; do not ask now based on an untested possibility.

Charts and unusual spreadsheet formatting are already accepted omissions. Unsupported cosmetic details beyond the named basic look, default-app name discovery, watchers and a theoretical residual pathname race without a demonstrated additional defect are debt candidates, not additional reasons for `change-spec`. No arbitrary cap may silently erase the agreed sheet reachability.

Re-review can pass when the revised spec fixes the local authorization/platform contract, one compliant parser/display flow and dependency inventory, exact shared schemas/type matrix/resource errors, and real producer-consumer test ownership. No new ADR or clickable fake is required for those selections within ADR-0003. Build remains gated on #5 integration.
