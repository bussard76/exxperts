## Findings and binding Developer instructions

1. **Private diagnostic contract.** For a non-`previewCode` error caught by the Word renderer, the child emits at most one newline-terminated ASCII line on stderr: `WORD_PREVIEW_DIAGNOSTIC <name>|<message>`. Allowed names are `Error`, `TypeError`, `ReferenceError`, `RangeError`, `SyntaxError`, and `UnknownError`; map every other name to `UnknownError`. Use `requestAnimationFrame is not defined` only if the original message exactly equals that string; otherwise use the fixed message `Unexpected renderer error`. Never serialize the original error, stack, path, or other message. The parent validates the complete line against these exact values, logs only the validated name and message, and ignores all other stderr for logging. This is a private diagnostic on the existing pipe, not a change to the exact-key IPC response. Cap line buffering and logging, handle split chunks and close/settlement ordering without losing a valid diagnostic, and retain the existing bounded OOM tail. A truncated, malformed, duplicated or unrelated stderr line must not be relayed; log at most one valid diagnostic per Word preview. Fixed fallback messages deliberately trade detail for privacy.
2. **End-to-end evidence.** Exercise an invented Word input through the real public route, actual child producer, parent stderr consumer and captured server logs, forcing an unexpected renderer error with an invented marker in the error text. Assert HTTP 422 `damaged_file`, an allowlisted name and fixed bounded message in the server log, and no marker in the log or response. Also verify the exact known message case, unknown name fallback and malformed/chunked stderr handling; do not use a fake child as the sole producer-to-consumer test. Keep existing sanitizer rejection and input, expansion, time and output limits intact.
3. **Visual limits and scope.** The first-page height and left-aligned page number are explicitly accepted as-is. Do not redesign them. The text-box fixture asserts successful HTML, not preservation of content inside rejected foreignObject. No dependencies, exports, routes or public IPC fields are authorized.
