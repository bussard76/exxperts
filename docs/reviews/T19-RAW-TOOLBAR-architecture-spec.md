## Prefactoring

None identified as necessary. Extend the current editor behavior in place; preserve the RAW exact-text source, revision/conflict handling and existing task cycle. Do not add a speculative adapter or new dependency.

## Findings

1. **Design and impact are incomplete.** Add `## Architecture impact` with the actual owning modules, exports and data flow, classify it against all level criteria, and identify the accepted UI/fake, exact interfaces and words plus Mermaid logic evidence or the specific signed exception. The Controller must obtain the level-2 decision if exports change. Do not treat the proposed smoke draft as signed design.
2. **The transformation contract is not buildable without choices.** Specify offsets (textarea UTF-16, half-open selection), selection direction and resulting selection/caret for all commands; line inclusion at a selection ending at the next line start; empty/whitespace lines and indentation; mixed selections (toggle all off only when all match, or per-line cycle); heading/quote/list interaction and numbered-list restart; and exact table insertion and link placeholders. Specify whether the task cycle continues to use its existing selection behavior and how task markers interact with list conversion. Give examples and tests for selected and unselected text, including a selection across multiple lines. The draft suggests choices (e.g. blank lines unchanged, all-matching toggle) but is unfinished and has no sign-off.
3. **Active state is ambiguous.** Define whether a range is active when all or any selected text/lines match, how mixed formatting is represented, and how caret and selection changes, keyboard movement, mouse selection and undo update it. Define inline delimiter handling at boundaries and nested/escaped or otherwise ambiguous Markdown, including no false italic on bold, and task versus bullet state. Bound the parser's supported syntax explicitly; do not require a full Markdown parser unless decided. A mixed selection with no deterministic policy causes misleading pressed state and potentially a destructive toggle.
4. **Native editing and failure need an executable contract.** Specify how the toolbar retains/restores focus and selection for mouse and keyboard, replaces the affected range with `insertText`, restores the requested selection, and ensures exactly one normal input update reaches `setRaw` and dirty/save state. Specify native undo/redo and button enabled state in supported browsers, handling `execCommand` unavailable/false or an absent input event without claiming success or corrupting draft, and selection behavior after Undo/Redo. Do not silently substitute a controlled React value update that loses undo. The current toolbar prevents mouse-down focus loss but keyboard activation and React-controlled updates need evidence.
5. **Acceptance must cross the real seam.** In addition to pure transforms, require an invented-data browser smoke using the actual toolbar, textarea, input handler and workspace save: select word, bold, verify exact persisted text, native Undo and Redo with persisted result; per-line H2/list, active/mixed selection updates, task cycle, copy, read-only and Find/Delete table behavior; selection after formatting, mode switch, and save/conflict protection. Cover command failure and clipboard failure without real services. Specify supported browser(s) and any differences; `execCommand` behavior and undo history cannot be established by pure tests. No tests were run in this review.

Questions for Sascha through Front if no existing sign-off answers them: (1) For a mixed selection, should a format apply to all lines unless all already have it, or toggle each line independently, and should pressed mean all or any? (2) Which browser(s) must support native formatting/undo, and what should the user see if the native edit or clipboard is unavailable? (3) What exact selection, blank-line and table-placement behavior is desired where the issue is silent? Front can present recommended concrete examples for approval instead of treating the unfinished smoke draft as a decision.
