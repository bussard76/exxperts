## Findings

No design-relevant gap remains in R2. These precisions bind the Developer:

1. The target GET `workspace-default` sets `folderRefused` from `roomFence(...).refused`, which is true for `refused` but **false for `moved`**; a `folder_moved` mapping alone therefore cannot prove a usable grant to the lost-response recovery. Make the existing view's current refusal indication cover an identity-unusable selected root and ensure the recovery treats missing/unknown indication as indeterminate. Exercise the real GET after a same-path lost response with both usable and unusable identity. Do not expose identity or infer usability merely from the path or policy ID.
2. Apply strict bounded decoding without coercion, including rejecting extra keys and values outside the representable range of the actual bigint stat fields. Hold and compare the opened object and selected path under the stated qualification; reject any uncertain observation. The tuple is evidence within documented assumptions, not a guarantee against metadata forgery or simultaneous identifier and timestamp reuse. Tests must report that residual limitation rather than claim absolute identity.
3. Qualification is an implementation evidence gate, not an assumption that a platform works. One concrete candidate to investigate is a narrowly identified local Linux ext4 mount: use existing APIs to identify the actual mount and provider, establish that Node's bigint `fstat` on the opened directory obtains a genuine sufficiently precise birth time rather than a fallback, verify no-follow and opened-object/path comparison, and document stable device/inode behavior across the intended restart and remount conditions. The [Linux kernel ext4 inode documentation](https://www.kernel.org/doc/html/latest/filesystems/ext4/inodes.html) describes inode creation time and its extra precision, but that alone does not establish what Node returned or rule out reuse; [Node's stat time documentation](https://nodejs.org/docs/latest-v22.x/api/fs.html#stat-time-values) expressly permits birth-time fallback. Demonstrate all required guarantees for the exact environment using primary documentation and available APIs, then independently measure selection, restart, replacement and reselection on disposable folders. If provenance, provider, lifetime or reuse criteria cannot be established without a new dependency or representation, refuse that combination and report the limitation to the Controller; seek separate authorization for any broader design. A passing sample, an ext4 label, or this candidate is not qualification, and no unmeasured platform or filesystem may be reported as supported.
4. The only additional choices beyond this amendment are a new identity representation or native dependency if the stated APIs cannot qualify a combination, or any new public contract, store, permission or changed flow. Return those for separate architecture authorization; do not silently relax qualification. Existing exact route errors, format coverage and RoomBox ownership remain governed by R3 and its binding review.

No product code, tests, builds, gates or exploit reproductions were run for this review. The acceptance tests and platform qualification remain future work; a passing spec review does not establish implementation feasibility or platform support.
