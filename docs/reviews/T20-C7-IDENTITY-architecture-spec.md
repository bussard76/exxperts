## Finding: the specified identity is not a document proof

C7 says after-navigation messages receive no bytes, and only a controlled new frame gets a copy. That includes navigation before the first readiness: it does not say only after the first delivery. R2 explicitly says source or ready alone is insufficient after arbitrary navigation. ADR-0004 accepts a rendered frame carrying its **one opened file** outside by self-navigation; that accepted residual risk does not establish that a replacement may receive an initial snapshot. Interpreting the C7 prohibition as applying only after a first delivery, or only to self-navigation after rendering, would narrow the accepted C7 guarantee. The contract register's first paragraph requires reconciliation of technical changes; the scope override specifically classifies a concrete protocol/contract/guarantee change as level 3.

The reported red is meaningful for that guarantee. The actual attached preview parent has the authorized snapshot; the test holds the real shell response, uses privileged parent script to set the existing `contentWindow.location.href`, and copies the visible fragment to an invented local replacement. The same iframe element, `src` attribute and `WindowProxy` remain; the replacement emits the expected ready and receives the 500-byte snapshot. `docs/reports/issue-20.md` records the attributed Attached-Tabs 0/1 failure. The preceding version changed `iframe.src`; its passing attribute comparison does not cover this navigation. The analogous premature HTML case is written but was not reached. Neither this review nor that report establishes child or native evidence.

The harness has more authority than untrusted preview content: it runs in the trusted app parent, chooses a local response and copies a fragment. A malicious parent that can itself read the snapshot can already disclose it; this test does not demonstrate an external attacker can cause that exact pre-ready replacement. In the product, the fixed shell runs before untrusted HTML or renderer file content is supplied; no product-reachable pre-ready navigator or response-substitution path has been demonstrated here. Once supplied, the approved HTML scripts and renderer content can cause their own frame navigation, and ADR-0004 explicitly accepts that one-file risk. The test is nevertheless a valid adversarial boundary test for the written guarantee, not evidence that its harness authority is an external threat. Trusted owner code, its HTTP response integrity and authorized server are assumed uncompromised; this review does not claim an exhaustive exploitability proof.

## Why the current exchange cannot settle it

The HTML standard specifies that navigation changes the `Window` behind a browsing context's `WindowProxy`, while cross-document message `source` is that proxy, not the particular document ([WindowProxy](https://html.spec.whatwg.org/multipage/nav-history-apis.html#windowproxy), [MessageEvent](https://html.spec.whatwg.org/multipage/comms.html#the-messageevent-interface)). Sandboxing without `allow-same-origin` gives an opaque origin ([HTML iframe sandbox](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)); `*` has no target-origin restriction, and posting to a newly navigated window has a readiness race ([HTML messaging](https://html.spec.whatwg.org/multipage/web-messaging.html#posting-messages)). A fragment is visible to the replacement; `src` and a load counter observe neither all navigations nor the active document synchronously. The actual red exhibits this indistinguishability.

A `MessageChannel` supplied by an unauthenticated ready is no proof: the replacement can create and transfer its own port. Sending a challenge or port to the `WindowProxy` after ready can deliver it to the replacement. A shell-generated random value unknown to the owner has no verifier; a secret in the fragment is not secret. An independently authenticated shell-to-owner channel might protect the gap between authenticating a genuine document and delivery, but its establishment and binding to that *particular* document must themselves be proved. A genuine shell nested or relayed by a replacement must not serve as an oracle for a forged port or challenge. Nor may a queued authentic ready followed by navigation cause the snapshot to be posted to the replacement. No such trust anchor, field exchange or document binding exists in the approved contracts. This is an indistinguishability argument for the specified exchange and stated checks, not a theorem that every conceivable browser architecture is impossible.

## Decision options and recommendation

**Recommend A: preserve C7, hold the affected build at this seam, and commission a bounded new authority design for Sascha's decision.** Keep Detach unavailable where its C7 acceptance depends on this; do not waive the red or alter its assertions. The candidate must identify a trust anchor available only to the genuine target document, demonstrate that a replacement cannot acquire, relay or replay it before first delivery, and bind the actual delivery endpoint to that document across navigation. If it needs a changed guarded response, authenticated exchange, route, server authority, privilege, origin policy or another responsibility, specify the exact level-3 delta and obtain an accepted ADR before implementing. This review has not found a document-instance proof that satisfies the frozen fixed shell, exact exchange and all existing constraints; it does not approve any hypothetical token, signature or channel construction. Fail closed on unavailable proof, timeout or unknown identity; do not disable an existing product preview without a separate authorized change.

**B: explicitly narrow the guarantee** to a precisely documented threat model and one-delivery behavior, accepting the pre-ready replacement case. This requires Sascha's decision and a reconciled accepted ADR and tests; it is a real guarantee change, not a precision clarification. Preserve ADR-0004's current risk separately. **C: change the preview isolation/delivery architecture** to one with a provable document-bound capability, retaining or expressly deciding any change to approved script execution, CSP and opaque origin. This also requires a concrete design and accepted ADR, with evidence for browser and desktop support. Neither B nor C is authorized by this review. No new ADR is authored under this dispatch.

For any A/C candidate the spec must define, before build: owner allocation and secret/authority origin; exact private ready, proof, delivery, rendered and failed fields and endpoint ownership; one-use and context/path/tab/host/frame checks; handling of empty, malformed, ambiguous, replayed, late, unknown and error states; and whether each message is queued or consumed at the relevant navigation point. A replacement must be unable to receive or forward the actual authority, including a genuine-shell relay. Only after proof may the owner synchronously consume the one-use delivery right and send a copied retained buffer over a document-bound endpoint; navigation between proof and receipt must either leave the copy with the authenticated document or fail closed, never retarget a replacement. Describe disposal and queued-message behavior, not merely `load` or `src` changes. Prove how authentic delivery survives or safely fails on browser teardown; a port alone does not prove its peer's identity.

Host transfer must destroy/disconnect and fence the old instance and its endpoint before a fresh authorized instance is initialized, bind listeners to the actual host document, retain the snapshot in the owner, and never refetch content on movement. Close/context exit removes listeners, timers and capabilities, aborts pending fetches and releases retained data. HTML must receive one UTF-8 copy only after proof and retain the HTTP frame CSP through `document.open/write/close`; demonstrate approved inline scripts and blocked external fetch/forms after the write, without `srcdoc`, blob/data or `allow-same-origin` relaxation. PPTX and Excalidraw need the same document proof with their actual bundled consumers and original-byte parser limits. The 30-second stall/error behavior, content-read count and approved self-navigation risk remain. If any condition cannot be demonstrated in the supported browser, the candidate fails closed and returns for decision; it is not a pass-by-design claim.

## Required future evidence

Use real authenticated route, real parent and real opaque shell/renderer and invented files; record exact candidate SHA, browser/environment and observations. Retain the original pre-ready `contentWindow.location.href`/copied-fragment regression unchanged for both Excalidraw and HTML, plus the prior `src`-attribute-change case. Include PPTX, genuine shell successful render and byte count, approved HTML script and post-`document.write` CSP/network controls, direct URL without bytes, size/policy guards and no extra content GET. Exercise wrong/foreign frame, forged/duplicate/late/stale ready/proof, relay and replay, held ready followed by navigation before delivery, and navigation after delivery; no replacement receives bytes and each legitimate instance receives at most one copy. Exercise close, stall, timeout, malformed/error, tab reorder and actual attached→child→Return transfers including first open in child and disk mutation after initial read. Instrument actual consumer outcomes and network requests; synthetic messages or two mocks are supplements only. Distinguish dispatch from receipt and check both sides of each race. Native and packed-platform evidence remain the separate R11/R15 obligations, not inferred from browser or source inspection.
