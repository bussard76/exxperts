## Prefactoring

No broad repository refactoring is justified. Keep the existing suite and full-gate entry points; isolate the experimental adapter and its coordination in the Controller-owned infrastructure. Do not change the shared gate shim or repository config until their exact necessity and impact are part of the approved design.

## Findings

1. **Coordination and decision required.** The current dispatch asks for simultaneous native and container full gates while the documented rule permits one at a time. A private container network alone does not authorize bypassing the host lock. Specify a proof-only coordinator that exclusively holds the same host-wide lock for the entire pair, blocks ordinary gates, admits exactly one native and one container child at the same immutable SHA, and waits for both and cleanup before release. Define precisely how the outer gate pool is acquired without recursively acquiring the same lock or deadlocking on `GATE_SLOTS=1`, how attribution reaches both records, and how crashes, signals, stale children and orphan containers are fenced before another gate starts. Treat this as a proposed protocol, not permission to bypass existing wrappers. Decide how noncooperating callers and other pools are excluded. Explicitly decide the bounded experiment exception in the accepted ADR; no general parallel policy follows from it.

2. **Image and dependencies are not buildable from the dispatch.** Freeze an image recipe and immutable base digest, architecture, package sources/versions and integrity, Node version and its verification, exact lockfile-derived Playwright version and browser revision/version and integrity, plus browser system dependencies. Specify how `npm ci` obtains verified dependencies without secret mounts or unrestricted run-time egress, and how its normal lifecycle (including MCP patch) runs. Browser download is best-effort in `scripts/install-chromium.mjs`; an install exit alone cannot prove a browser exists. Resolve the image and browser from the actual immutable proof SHA, not this worktree's modified lockfile. If offline artifacts cannot be obtained under these bounds, fail closed and report rather than weaken coverage.

3. **Isolation and resources need an executable contract.** Define each run's exact source, private temp/HOME/cache paths, ownership and cleanup. A read-only source mount alone cannot hold build outputs: use a verified disposable writable copy, never the live checkout, with no host user state or secrets. Make the container network namespace private with loopback enabled and no published ports or external egress, and verify tests do not require external services. Ports 53692 and 1455 must be bound concurrently in their respective namespaces and exercised by the real relevant smokes. `scripts/run-smokes.mjs` uses fixed `exxperts-smoke-timings.json` and `exxperts-smoke-failures` under `os.tmpdir()`; audit hard-coded paths as well as TMPDIR, and prove the two runs cannot share or overwrite them. Specify CPU, memory, disk, PID and shared-memory limits, preflight headroom, pressure/timeout abort criteria and monitoring so Docker does not starve the native run or other host work. Missing prerequisites, ambiguous source identity, unsafe mounts or inability to isolate must abort before execution.

4. **Freeze proof and result interface.** At minimum specify request fields: immutable full SHA, run ID, mode (`native` or `container`), exact unfiltered command, clean source location, environment allowlist and private paths, image digest for container, attribution and resource limits. Result fields: those identities, start/end timestamps, exit/signal, install/build/smoke status, per-smoke outcomes and skips, browser executable/version and observed browser execution, log locations, cleanup status and failure reason. Define empty, missing, duplicate, malformed or contradictory results as failure, never success. Retain raw logs and statuses for failures, timeouts and interruption without exposing secrets or real data; never mask command exit with logging or cleanup. Stop children, remove only experiment-owned containers/paths and verify no survivors before releasing admission; report cleanup failure and keep admission closed until resolved.

   The independent Tester must establish an unfiltered native baseline and then a genuinely overlapping native/container pair on the same immutable SHA, equivalent invented inputs, environment and normal `npm ci` lifecycle; record unavoidable platform differences. Both simultaneous runs must independently pass, preserve the baseline smoke inventory, assertions and skip set, and include actual browser-backed execution. Compare per-smoke output and skips, investigate discrepancies and preserve all failures; the existing isolated-rerun rule does not by itself demonstrate equivalence. Show overlap timestamps, fixed-port and temporary-path collision proof, no external access, resource observations, and cleanup. An image build, isolated unit test or serial pair is insufficient. The Controller and independent Tester must review evidence before a separate policy decision, with no cap change implied by a pass.

## Options for Sascha

A. **Recommended:** accept a narrowly scoped Docker proof design and an exclusive, host-lock-held two-child experiment; retain normal one-gate policy until independent evidence and a later explicit decision.
B. Retain the current native single gate and defer Docker and overlapping proof.
C. Choose a different isolation or coordination design; document its exact protocol and bounds before approval.
The Controller should present the options and record the chosen design in an accepted ADR; this review does not decide for Sascha.
