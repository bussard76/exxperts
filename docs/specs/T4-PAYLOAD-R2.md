## F1 correction and artifact ownership

F1 is a real consumer defect: the old 187-location deletion set was exclusive only against other server file-package roots. The archive runtime still imports proper-lockfile, which needs graceful-fs from that set. Independent review found 28 overlaps with other production roots, with 202 additional code/resource files beyond the proposed manifest/notice retention. Removing graceful-fs's code while retaining its manifest reproduced `MODULE_NOT_FOUND` on the public proper-lockfile import.

The transform has exactly one output owner: **`apps/desktop/build/server/app/` after fresh archive extraction**, at the existing Step 2a call in `apps/desktop/scripts/package.mjs`. The extraction creates the private desktop copy before `pruneDesktopPayload(appDir)` runs. It is not performed by ordinary `bundleServer`, source development, package postinstall, packed-dependency installation or `scripts/bundle-release.mjs`'s shared installed-root bundling. Source install, lock-driven release-root installation, source tarball, release archive/CLI and `vendor/node/` remain untouched by this reduction. No hardlink/symlink back to those inputs may permit writes through the stage.

Keep the current public synchronous signature and behavior of `pruneDesktopPayload(appDir, { log, maxFiles } = {})`: normal return after complete validation or a thrown error; no Promise, new export, callback, option or asynchronous caller. Production retains the default `DESKTOP_MAX_FILES = 2_500`; no larger override in package integration. Place the private transform inside the existing desktop prune module, using the packaging host's **already available esbuild 0.28.1 `buildSync`**. Do not add esbuild to the shipped runtime graph. No new module or generalized tracing/pruning framework is needed; `package.mjs` keeps its synchronous call and error handling.

1. **Inspect the complete private stage before mutation.** Resolve the selected stage root and every package/input/resource by physical path inside it; reject escaping symlinks/foreign realpaths, unknown package versions, missing required inputs or unexpected public entry shape. 2. **Derive a conservative desktop retention set.** Walk the actual installed location-resolved dependencies, optional dependencies and peers through the existing `shippedPackageDirs` seam. Start with all other shipped roots plus the actual retained server, children, doctor/searxng and desktop helpers; include their file-relative/dynamic/native dependencies, not only graph roots. Shared packages remain complete under the existing generic prune policy even if the bundle also embeds their code. Retain all original selected manifests and named notices at their original nested locations: frozen measurement was 252 manifests, not a permanent whitelist. Preserve any new shared location in the final graph; recompute the 65/187 split and count. Only existing optional `recheck-jar` exclusion is authorized.
3. **Build the full pinned public Node entry in memory.** Resolve `require("exceljs")` from the stage to ExcelJS **4.4.0**'s original `node_modules/exceljs/excel.js`; verify manifest/main/version and expected original input provenance. The generated output replaces only the staged **`node_modules/exceljs/excel.js`**.
4. **Audit the candidate before writes or deletions.** Review every metafile input's package/location/version against the installed graph and lock; record input digests and output digest. Refuse unresolved/nonbuiltin external imports, compiler warnings, foreign-root input, new/unreviewed nonliteral loads, `__dirname`/`__filename`/`require.resolve` or equivalent own-location behavior. Reuse the existing audit approach privately without adding public helpers or broad audit exceptions. The existing server audit alone does not cover this new output, and absence of textual matches is not a completeness proof. Check public `require` exports (Workbook, ModelContainer, stream readers/writers and enums), constructor/behavior shape and ESM default interop against the original package in separate subprocesses; broad API equivalence is not inferred from one xlsx fixture. Unknown input shapes fail before reduction; review/update the pinned design rather than silently allowing them.
5. **Prepare all retained entries, resources and notices.** Keep the original ExcelJS manifest byte-for-byte and every advertised runtime target, including **`browser: "./dist/exceljs.min.js"`** and its applicable attribution. No permission here to delete that target or edit the manifest to conceal it; count this additional file and any required companion in E below. Preserve the exact owned saxes/xmlchars paths and all non-Excel resources described below. Materialize the complete provenance-bearing **`node_modules/exceljs/excel.js.licenses.txt`** from verified original texts before their inputs can be lost. Preserve original source files/notices wherever the applicable terms require them. An unverified or absent notice is a pre-reduction failure, not an empty sidecar or license-label substitute.
6. **Commit the validated private candidate, then prune conservatively.** Once all preflight/audit/notice conditions are satisfied, write the staged bundle and sidecar and apply only the proved desktop-exclusive code reduction inside the stage. Keep every original selected manifest/named notice; retain shared code, advertised entries, parser closure and required source notices. Reuse existing generic-pruning rules only for files proved nonruntime/nonnotice under this plan; blanket removal of tests/examples/years/locales/distributions is not authorized. No trace-derived whitelist of es-abstract editions: public ExcelJS actually exercised 81 es-abstract inputs including `2024/IsCallable`. Never infer that an unobserved file is unused.
7. **Validate the actual result and fail the package on any gap.** Run existing `checkServerFiles`, lock membership/native checks and the actual whole-app counter unchanged, plus physical entry/resource/consumer execution checks below. They must distinguish deliberately retained manifest-only inlined dependencies from executable entries still needed by another consumer; no broad suppression of missing imports. Metadata success alone is insufficient. Incomplete/over-budget stages cannot proceed to an installer or be reported as accepted; regenerate a fresh stage after failure. Normal `package.mjs` does not publish. No packaging or deletion is performed by this specification task.
